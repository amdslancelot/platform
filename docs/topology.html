A reusable platform layer — four workloads today, additive onboarding for the next

A ground-up re-imagining of platform infrastructure — how I'd design one, drawing on 10+ years of engineering. Deliberately a minimum viable platform (MVP): the smallest build that proves the pattern, with a clear upgrade path. It owns everything two or more apps stand on; each app declares only its own thin slice — a namespace, a Host(...) rule, a database role, and one deploy hook.

What this repo owns

The platform repo is the single source of truth for shared infrastructure: the node, single-node k3s, Traefik, the wildcard cert, the shared Postgres, and the :9000 webhook listener. App repos own their own build + deploy — only what two or more apps stand on lives here.

Onboard a new app — 4 steps

  1. kubectl create ns <app>
  2. a Host(...) Ingress rule (wildcard cert covers it)
  3. PROVISION_APPS=<app> (additive, idempotent)
  4. a hook in webhook/hooks.json

Additive throughout; the next app needs no cluster-wide change.

TLS & security posture

  • Wildcard cert is Traefik's default cert — app Ingresses carry no tls: block; a Host(...) rule is all they declare.
  • :9000 webhook is plain HTTP; security is the HMAC secret, never TLS.
  • Postgres runs with no TLS by design — traffic never leaves the trusted node/cluster network.

Why it's built this way — design trade-offs

One shared cluster

A single-node cluster is one failure domain with no HA — but it removes per-app cluster cost and ops entirely and forces clean multi-tenancy (namespaces + per-app DB roles). The tenancy contract scales to more nodes without changing the app contract.

Platform repo = source of truth

Shared infra used to squat in whichever app repo needed it first (Postgres in one app, cert-manager buried in another's deploy script) → duplication and unclear ownership. Centralizing it draws a hard platform/app boundary: apps stay thin and onboarding is self-service.

No image registry

Build on the node and import into k3s containerd (imagePullPolicy: Never, localhost/<app> so containerd never normalizes to docker.io/library and pulls). No registry to run, secure, or pay for and no pull credentials. A registry (GHCR) can slot in later with no app change.

Wildcard = Traefik's default cert

One wildcard means a bigger blast radius and no per-app cert policy — but apps declare zero TLS config (no tls: block) and every new subdomain gets valid TLS automatically. TLS becomes a platform concern, not an app concern.

Shared Postgres, least-privilege per app

One server is a shared resource — but a per-app <app>_rw login-only role scoped to its own database (PUBLIC connect revoked; no SUPERUSER/CREATEDB/CREATEROLE) gives real isolation without N database servers. Provisioning is additive, idempotent, and self-verifying — the script asserts the isolation at the end. No TLS by design — DB traffic never leaves the node.

Trigger and gate, decoupled

Per-app triggers (Actions-SSH / CI→webhook / native webhook) look inconsistent — but each app keeps the trigger that fits it while sharing one :9000 HMAC-signed webhook. Trigger is separate from gate (test-gate = build must pass; release-gate = v* tag) — two axes mixed per app.

Open decisions & what's next

Open decision — where the analysis worker runs

transigen's Python worker runs locally (residential IP) and reaches Postgres via port-forward to the staging data plane — it has never run against prod, and deploy/ ships no worker manifest. Deploying it to the cluster would drop the tunnel, but must first clear whether a datacenter IP trips YouTube's bot-check (the original reason it runs local). Deliberately unsettled.

Push now, GitOps later

Push-to-deploy is imperative and can drift; GitOps self-heals and resists drift but adds a controller, a registry, and complexity. Prove it in the local minikube mirror (where a reset makes mistakes free), then promote — deliberate sequencing, not an absence of the idea.

What's next

  • Backup/restore for the shared Postgres — today the biggest single point of failure.
  • GitOps (Argo CD/Flux) for declarative rollbacks, replacing the webhook.
  • A real secret store instead of .env → Secret at deploy time.

A reusable platform layer — one shared single-node k3s cluster, one wildcard-TLS domain, one signed deploy webhook — that any number of apps can stand on.
